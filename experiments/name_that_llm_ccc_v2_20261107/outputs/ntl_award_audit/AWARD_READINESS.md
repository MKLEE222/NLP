# 获奖准备度审计：有内部提升，距离奖项证据仍有关键缺口

2026-11-07。此次审查实际读取代码、重用五个保存的外层模型完成批次压力实验、补做同特征线性对照、检查错误类别并修复部署缓存身份问题。未调参或重训原模型；补充的线性控制属于审计研究。原训练协议、指标和模型权重保持。

## 判断

当前是**有真实内部收益、可运行的研究原型**。57.46%是多候选比较后选出的工程版本；注册主版本为56.49%。现阶段缺乏当前Kaggle公开榜分数和最终私榜证据，无法判断铜牌、银牌或奖金前十的距离。方法名称、内部bootstrap正区间和工程可运行性均不构成获奖证据。

此前汇报应更突出两个条件：核心收益依赖整批文本的可恢复分组；实际默认版本的分组失效压力检查不完整。本审计补测并明确了这两个问题。

## 1. 最严重的风险：批次依赖

以下使用**同一2699行外层预测对象、同样五个冻结模型**，只改变推理批次组织，完整分类头及权重不变。

| 推理方式 | 分组Qwen BASE | 默认XGB_FULL | 原始独立Qwen |
|---|---:|---:|---:|
| 每个外层验证折整批推理 |55.64%|**57.46%**|41.78%|
| 每32条单独恢复分组并推理 |40.45%|**42.30%**|41.78%|
| 每8条单独恢复分组并推理 |40.49%|**42.82%**|41.78%|
| 严格单条推理语义 |41.78%|**43.93%**|41.78%|

单条向量化诊断与实际逐条调用在每折两个样本上核对一致。32条批次下，约48.2%的默认预测与整批结果不同。批次顺序和组成是模型合同的一部分。实际当前预测入口对整个输入文件分组，骨干小batch编码本身不触发这个问题；后续部署若把最终分类也切批会严重改变结果。

这组结果证明57.46%是特定整批协议下的内部成绩。它不预测私榜一定降到42%；私榜的prompt密度、类别构成、长度和文本分布仍未知。官方说明已经明确隐藏测试各模型数量不均，公私榜模型混合不同，因此完整18类均衡prompt的训练结构不能直接推出测试结构。

其他固定诊断：随机保留一半时XGB54.97%，保留20%时48.88%；每个真实prompt只留一条时41.26%。这些删减情形的评估行和类别支持数不同，不能将全部差值归因于分组一个因素。完整条件、类计数与区间在`stress_results.json`。

当前支持域门控主要检查组大小2–18及原始PCA范数的99%边界。它不能证明分组语义正确，也没有处理类别先验偏移。整批中约98.5%行通过，不能把这一覆盖率称为高可信分组比例。去掉门控的点估计56.57%，带门控56.49%，目前没有额外增益证据。

## 2. 验证已经被多轮研究消耗

同一150个prompt反复用于方案、特征、模型和消融选择。分组五折能避免直接将同一prompt跨训练/验证使用，但不能消除研究过程对整个语料的适配。新随机种子、新划分或更多bootstrap都不会重新制造一套未见测试数据。

57.46%的XGB模式是观察固定候选结果后确定的工程默认项，注册主终点仍是56.49%的双树受约束项。八候选Bonferroni报告没有覆盖此前多轮方法搜索。当前固定预测的bootstrap反映评估prompt重采样波动，没有包含重训、表示选择和整段研究选择过程的不确定性。五折训练集重叠，也不能当作五次独立研究。

代码审查没有发现外层金标签直接用于基础头、PCA或树拟合；训练内三路prompt交叉拟合和内部早停是真实实现的。问题在证据范围和选择暴露程度，不能据此将现有结果当作新语料上的确认性成绩。

## 3. 对照实验存在混杂，原创性证据不足

此前的纯树控制使用217维压缩/文体/分组特征，而强Qwen头使用完整7168维表示。43.53%对55.64%同时改变了表示和分类器，不能把差值单独解释为树算法能力差。

本次补做同217维特征、训练折内StandardScaler、固定C1的线性LR：44.45%，与纯树43.53%的成对差值区间为[−0.97,+2.89]pp。重构的特征已精确复现保存的纯树预测。因此这项控制没有分离出明确的树／线性优劣，更显示压缩后的独立头不等于完整表示的强基线。线性控制的C没有搜索，属于固定审计补充。

仍缺：相同交叉拟合margin、相同输入和预算的线性纠错、概率校准、学习权重的强融合；以及同类公开残差提升管线。简单75/25融合了一个较弱的树头，不能代表成熟集成方案的上限。

内部训练60.1%/校准54.0%的数字可作容量诊断，但纠错训练和校准所用基础头训练规模不同，不能将差距直接视为严格隔离的抗过拟合证明。完整外层和独立评估更关键。XGBoost/LightGBM、初始margin、交叉拟合及中心化都有成熟先例，当前支持的是具体组合实现，而非已成立的全球方法原创性。

## 4. 错误集中在弱类，当前纠错只是净改善49条

默认XGB纠正167条BASE错误，同时将118条原正确预测改错，净改善49条；默认版本仍错1148条，其中629条发生在同一厂商模型之间。

| 弱类 | OOF召回率 |
|---|---:|
| claude-fable-5 |29.53%|
| glm-5.3 |34.00%|
| glm-5.3-flash |36.67%|
| gpt-5.6-sol |41.33%|
| gemini-3.7-flash |43.33%|

例如Gemini3.7/3.8相互混淆76条，GLM两个版本相互混淆53条。指标是18类宏平均召回，弱类直接限制排名。后续更值得研究准确版本、匹配生成设置、相近模型成对覆盖的数据和任务监督表征，而非继续堆树深度。

第三轮4998条外部Claude数据只进入文体路线；当前Qwen／树版本仍仅以官方2699条训练。只增加Claude可能伤害相似的GLM类，需要成对/全类覆盖与严格来源核验。当前Qwen骨干冻结，尚未做指纹任务LoRA或监督表征学习，也没有真正多样的独立骨干集成。

本轮额外排除了一个假想瓶颈：训练文本token长度最大381，超过512的为0条，所以当前训练语料没有被512-token截断。提高长度上限不应成为此阶段的主优化方向。

## 5. 已确认并修复的实现问题

旧编码器缓存命中只看输入文件哈希，未核对本次传入的模型目录、tokenizer或编码实现。不同编码器若复用同数据路径，存在静默读取旧特征的风险。这不推翻当前已登记的固定特征成绩，但影响后续模型切换的可信度。

已在活动v4预测入口增加：头文件哈希、实际配置/权重索引/四个权重分片、tokenizer文件、编码实现身份、缓存数据/内容哈希和编码器stamp检查。错误骨干、错误tokenizer身份和错误缓存stamp会被拒绝。当前3个官方样例重新编码的锚点与旧特征误差为0，修复前后预测一致。训练特征按原登记SHA固定；没有声称本次重新编码全部2699行。

验证记录为`encoder_fix_verification.json`、`deployment_verification.json`。新manifest绑定当前本地模型产物；重新训练或换编码器后需重新验证和绑定。旧三轮研究文件保留；该修复针对活动部署入口。

## 6. 平台与强基线缺口

目前只有本地脚本与3行格式/推理检查，没有一份实际完成Kaggle离线重跑并获得成绩的提交。缺少自包含Notebook、Linux依赖/离线wheel与模型资产组织、Kaggle实际GPU精度和输出锚点核对、完整隐藏测试运行时间与显存记录。原自定义joblib模块依赖跨轮脚本，默认推理还计算未使用的多个模式，部署链应精简。

[官方规则](https://www.kaggle.com/competitions/name-that-llm/overview/abstract)要求Notebook重跑、禁网、9小时内完成。当前公开榜API返回401，网页未提供可读排名，因此没有得到真实前十或奖牌线。

[公开方案页面](https://www.kaggle.com/code/alexchilton/name-that-llm-0-662-all-public-what-failed)显示最佳公开分约0.666；已审查过的[0.604方案](https://www.kaggle.com/code/saddamaditya/name-that-llm-two-stage-lora-hungarian)完整集成也尚未复现。本地0.5746与这些榜单分数不能直接相减。强基线应在同一平台比较；若其任务微调头已用全部官方数据训练，直接拿来做官方训练集本地CV会污染验证，需要原生OOF资产或重新按折训练。

## 先后顺序与通过标准

| 优先级 | 应做的事 | 可验收结果 |
|---|---|---|
| P0 | 冻结当前权重，做自包含Kaggle离线入口 | 官方完整重跑成功，获得固定BASE与XGB版本的真实分数、排名、时耗、资源及锚点一致性 |
| P0 | 为后续选择保留新证据 | 新prompt/独立来源的盲测合同，或预先限定用途的平台验证；现150prompt继续按开发资料管理 |
| P1 | 修复分组结构脆弱性 | 训练内模拟稀疏/非均衡组，对分组可信度和残差收缩做同预算对照，整批和稀疏批次均报告 |
| P1 | 复现强公开参照并解决弱类 | 同平台/同划分强对照；弱类召回、数据来源与监督适配的真实增益，避免公开任务权重污染本地CV |
| P1 | 补齐成熟校正/集成对照 | 相同输入、相同OOF信息、相同预算的线性纠错、校准与学习融合，确定树和自定义模块各自贡献 |
| P2 | 精简与再优化 | 移除缺乏增益证据的部署组件，之后再调树参数或增加互补骨干 |

现金奖由最终前十决定，奖牌按最终排名规则决定。现在的结论是“可继续验证的原型”，尚无依据宣称获奖级；最重要的下一步是获得可信的平台定位与跨批次泛化证据。
