# 第二轮改进结果：固定 SVM 获得内部提升，CCC 门控收益仍有限

2026-11-07，使用官方 2,699 行训练数据。已完成五折嵌套 prompt 分组评估、冻结 MiniLM 对照、实际冻结 CCC 模块调用和全量模型导出。第一轮代码、协议和结果均保留。

## 同折比较

150 个 prompt 按种子 20261110 打乱后分为五折，每个外层训练集有 120 组。内部再留 24 组开发，其余用于拟合和选择，随后在全部外层训练组重拟合，再评分外层测试组。所有 TF-IDF、标准化和分类器均在对应训练分割拟合。MiniLM 使用本机固定检查点，冻结编码，无标签拟合。分类预测不使用真实 prompt ID 或每组一标签约束。

| 固定方法 | 五折 OOF 平衡准确率 | 相对同折 B0 | prompt 成对 bootstrap 95% 差值区间 |
|---|---:|---:|---:|
| B0：字词 TF-IDF + 15 文体特征，LR | 34.11% | — | — |
| V1：扩展到 85 文体特征，LR | 34.04% | −0.07 pp | [−1.70, +1.59] pp |
| V2：85 文体特征 + LinearSVC C=0.5 | **35.93%** | **+1.81 pp** | **[+0.29, +3.37] pp** |
| V3：85% V1 + 15% 冻结 MiniLM 分类器 | 34.15% | +0.04 pp | [−1.59, +1.70] pp |
| 嵌套门控实际选出的模型 | 34.15% | +0.04 pp | [−0.52, +0.56] pp |

V2 五折分别为 35.37%、34.81%、36.12%、36.11%、37.22%，每折均高于 B0。其 OOF BA 的 95% 区间为 [34.22%, 37.56%]；对三个固定候选作 Bonferroni 单侧 98.33% 调整后，相对 B0 的重采样下界仍为 +0.15 pp。调整属于固定预测的报告分析，未改变模型或参数。

这个结果支持优先继续 V2。文体特征单独增加、冻结语义表示融合均未建立收益。V2 与第一轮 36.45% B0 使用不同分割，应比较本轮同折 34.11% B0；不能直接拿两轮绝对分数判断升降。

全部训练数据已在第一轮参与研究判断。这次评估为预先固定配置下的内部 prompt 泛化估计，尚缺独立新数据或隐藏测试验证；bootstrap 条件于这套 OOF 预测，未覆盖重训所有模型的随机性和研究过程选择偏差。五折结果、逐类召回、区间和完整参数见 `results.json`、`PROTOCOL.md`。

## CCC 部分实际结果

嵌套采纳门控在五折中选了四次 B0、一次 V2。单折内部仅 24 个 prompt，保守门槛经常未通过；最终门控整体 34.15%，相对 B0 的差值区间覆盖零。因此，固定 SVM 的提升与 CCC 门控收益应分别判断，目前门控没有建立额外增益。

补充实验实际以只读方式导入原项目的 `aggregate_claim_compiler.fast_rate_interval`。针对预先指定的 V1 与 B0 OOF 比较，预测一致的文本对差值贡献已知为零；对 1,204 个分歧文本，按 prompt 审计标签，以冻结模块计算成功/失败/未解决状态的比较界。通过共同逻辑锚点保证变换后分母定义，发布符号与原有限总体普通准确率差的符号相同。该合同的对象是固定总体的普通准确率排名，未将其提升为未知 prompt 的平衡准确率保证。

优先揭示分歧最多 prompt 的策略与 100 个随机顺序全部需要审计 150 组/2,699 行，**采证节省为零**。二者最终均正确判定 V1 略低于 B0，普通准确率差 −0.0741 pp。该近似平局需要几乎完整证据，显示此任务上精确排名的采证价值有限。策略读取预测和组信息，直到审计才读取金标签；没有用金标签安排审计。

原核心哈希 `3b2a81f803de2aaa3eb522327128b68016bb6c08522a34a2c174010dc240b0c3` 在调用前后相同，原稿哈希仍为 `ead0474d68b19c3ba0ac60b9251e392e14bee8f2c201d74c6db5e2e527eefd63`。本轮调用的是冻结核心中的区间计算组件，尚未接入完整合同验证和序贯规划编译器。没有从这一接口实验推导 CCC 全套核心的性能结论。

## 可直接使用的模型

`V2_fulltrain.joblib` 约 21.6 MB，包含在全部 2,699 行上拟合的字词向量化、85 特征标准化和 SVM。文件 SHA-256：`2b31c97248721b83e440db2f91bb26d88cc9a688f23177f7f16a81cffa769207`。

保存后重新加载，官方三个样例文本的预测完全一致；`sample_submission.parquet` 的字段为 `id,model`，顺序与官方样例一致。这三行仅是格式与推理检查，没有隐藏测试成绩，也没有提交 Kaggle。

```powershell
python outputs\ntl_ccc_v2\predict.py outputs\ntl_ccc_v2\V2_fulltrain.joblib input.csv output.parquet
```

输入需含 `id,text`，无需 prompt ID。模型推理无需 GPU 或 MiniLM。

完整重跑入口：`run_portable.py <官方ZIP> <本地MiniLM检查点目录>`。检查点固定 revision `1110a243fdf4706b3f48f1d95db1a4f5529b4d41`，每个文本首尾各 160 词的表示取平均，编码上限 256 wordpieces。该公开模型的用途和截断规则见 [MiniLM model card](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)。本轮编码使用 GPU，五折训练主要用 CPU，评估共约 280 秒。

后续优先保留 V2 作为分类基座，在新 prompt 数据或独立隐藏测试上验证；MiniLM 融合与当前精确采证排序暂停扩展。若继续优化 CCC，先将“全局精确排名”换成有实际决策意义且预声明的差值容忍区间，并比较同证据预算的标准选择策略，再考虑规划层。该调整应另立新协议。
